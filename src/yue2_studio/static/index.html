QUICK START
Welcome to your studio.
Make an original song
Describe the sound in Style, add lyrics with [Verse] and [Chorus] tags, then choose Create song. Full mode creates melody and harmony before audio. Plan only creates an editable score without rendering audio.
Give a melody a new sound
Choose Create a cover and upload a recording. Transcribe it, then use Review melody in the completed run. You can also import native ABC directly. Check the score and use Prepare melody to remove chords, keeping both melodic voices by default. Enter the target style and lyrics, then create your cover. Full mode can keep the score’s harmony too.
Write with an LLM
Open LLM Runner, choose a provider, enter an API key if needed, and refresh the model list. Custom model IDs are supported. Test the connection, describe your idea in the writing room, and review the editable draft before applying it. You can refine the current lyrics or generate only a style.
Tags & timing
[Verse] and [Chorus] are the official example’s section cues. Other section tags are editable text cues, not guaranteed control tokens. Put vocal delivery, instruments, mood, language and intended BPM in Style. Yue2 has no exact-duration slider or singer-cloning input.
Closing Studio
Closing the last Studio tab stops the server after a 15-second grace period. Refreshing or keeping another tab open keeps it running. Active songs, batches and writing requests finish before automatic shutdown. To return, use Start Yue2 Studio.bat.
Your work stays organized
Each GPU job uses a fresh folder in runs/studio. The library keeps audio, scores, exact requests, token arrays, latents, logs and provenance. Cancel stops that job’s worker. Interrupted jobs need a fresh run. Local draft autosave and exported project JSON exclude API keys. Save a project to make a portable backup; original recordings remain in this workspace.
Local LLMs & memory
Use LM Studio, Ollama, or a custom OpenAI-compatible server for local models. Start that server and load a text model before connecting. If it shares your music GPU, unload its model before a large music run. Ollama requests use keep_alive=0 to release the model after writing.

GGUF needs a separately installed audio.cpp engine. This panel downloads model files only; it does not install or build audio.cpp. Install the engine outside Studio, then connect its executable below. Downloading a model alone does not complete GGUF setup. Torch does not need audio.cpp.
1. Connect your installed audio.cpp engine
Standard build folders are detected automatically. Model downloads install weights, not the engine or CUDA drivers.
Need to install the engine?
Install a Yue2-capable audio.cpp build. On Windows, building requires Visual Studio C++ Build Tools, CMake/Ninja, and CUDA Toolkit for NVIDIA. Keep runtime DLLs beside the executable, then paste its full path above.
